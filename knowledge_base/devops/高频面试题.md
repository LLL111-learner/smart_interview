## 一、Linux基础（5题）

### 1. 请解释Linux文件权限体系，如何使用chmod和chown命令？特殊权限（SUID/SGID/Sticky）分别有什么作用？
- **难度**：基础
- **考察点**：Linux权限管理
- **要点**：三组权限（Owner/Group/Others），rwx对应读写执行（4/2/1）。chmod修改权限（数字法如755、符号法如u+x），chown修改所有者和所属组。SUID（4xxx）：执行时以文件所有者权限运行（如passwd命令）。SGID（2xxx）：文件以所属组权限执行，目录中新建文件继承目录的组。Sticky Bit（1xxx）：目录中只有文件所有者和root能删除文件（如/tmp）。

### 2. Linux系统中如何排查CPU和内存使用异常？请描述你的排查思路和常用命令。
- **难度**：中等
- **考察点**：系统监控和问题排查
- **要点**：CPU排查：top/htop查看进程CPU占用，确定高CPU进程 → pidstat查看进程详情 → strace/perf分析系统调用和热点函数。内存排查：free -h查看整体内存 → top按%MEM排序 → /proc/PID/status查看进程内存详情 → vmstat观察swap使用情况。关键指标：load average（负载）、%wa（IO等待）、%si/%hi（中断）、buff/cache（缓存可回收）。

### 3. 请解释Linux的进程、线程和协程的区别。什么是僵尸进程和孤儿进程？如何处理？
- **难度**：中等
- **考察点**：进程管理
- **要点**：进程是资源分配的基本单位，线程是调度执行的基本单位（共享进程资源），协程是用户态的轻量级线程。僵尸进程：子进程退出但父进程未调用wait()回收，状态为Z。处理：kill父进程让init回收、编写正确的信号处理（SIGCHLD）。孤儿进程：父进程退出后子进程被init(PID 1)收养，一般无害。查找僵尸进程：`ps aux | grep Z`。

### 4. 请解释Linux中软链接和硬链接的区别。inode是什么？
- **难度**：基础
- **考察点**：文件系统原理
- **要点**：inode存储文件元数据（权限、大小、时间、数据块指针等），不含文件名。硬链接：新目录项指向同一个inode，共享数据块，不能跨文件系统，不能链接目录，删除原文件不影响硬链接。软链接（符号链接）：新文件存储目标文件的路径名，可跨文件系统，可链接目录，原文件删除后软链接失效（悬挂链接）。`ls -i`查看inode号，`ln`创建硬链接，`ln -s`创建软链接。

### 5. 请描述Linux系统的启动流程。systemd和SysVinit有什么区别？
- **难度**：中等
- **考察点**：系统启动原理
- **要点**：启动流程：BIOS/UEFI → GRUB引导加载器 → 加载内核和initramfs → 内核初始化 → init进程（PID 1）→ 启动系统服务 → 登录界面。SysVinit：串行启动脚本，运行级别（runlevel 0-6），/etc/init.d/脚本。systemd：并行启动，基于依赖关系，unit配置文件，支持socket/dbus/timer激活，cgroup资源管理。常用命令：`systemctl start/stop/enable/status service`。

## 二、Shell脚本（3题）

### 6. 请编写一个Shell脚本，实现日志文件自动清理（保留最近7天的日志，清理前做备份压缩）。
- **难度**：中等
- **考察点**：Shell编程实战、运维自动化
- **要点**：find命令查找过期文件（`find /var/log/app -name "*.log" -mtime +7`），tar压缩备份到归档目录，rm删除源文件。脚本需要：变量定义日志目录和保留天数、日志输出记录操作、错误处理（检查目录是否存在）、crontab定时执行。进阶：使用logrotate配置实现更优雅的日志管理。

### 7. Shell中的变量作用域、管道、重定向和进程替换分别是什么？
- **难度**：中等
- **考察点**：Shell语法深度理解
- **要点**：变量作用域：局部变量（local）、环境变量（export）、特殊变量（$0/$1/$?/$$/$$!等）。管道：`|`将上一个命令的stdout作为下一个命令的stdin，每个命令在独立子shell中执行。重定向：`>`覆盖、`>>`追加、`2>`错误输出、`2>&1`合并输出、`<`输入重定向、`<<`Here Document。进程替换：`<(command)`将命令输出作为文件描述符使用。

### 8. 请用Shell/AWK/Sed处理以下场景：从Nginx访问日志中统计HTTP 500错误最多的前10个URL。
- **难度**：中高
- **考察点**：文本处理能力
- **要点**：`awk '$9==500 {print $7}' access.log | sort | uniq -c | sort -rn | head -10`。awk字段提取（$7是URL，$9是状态码），sort排序，uniq -c计数，sort -rn按数值降序。进阶：按时间段统计、正则匹配特定模式、生成报表。sed的使用：`sed -n '/pattern/p'`过滤行、`sed 's/old/new/g'`替换。

## 三、Docker/K8s（5题）

### 9. 请解释Docker的核心原理。容器和虚拟机有什么本质区别？
- **难度**：中等
- **考察点**：容器化技术原理
- **要点**：Docker利用Linux内核特性实现隔离：Namespace（PID/Network/Mount/UTS/IPC/User六种命名空间实现资源隔离）、Cgroups（限制CPU/内存/IO等资源使用）、UnionFS（分层文件系统实现镜像层叠）。容器共享宿主机内核，启动秒级，占用资源少；虚拟机通过Hypervisor虚拟化完整OS，启动分钟级，占用资源多但隔离性更强。

### 10. Dockerfile的最佳实践有哪些？如何优化镜像大小？
- **难度**：中等
- **考察点**：Docker镜像构建优化
- **要点**：基础镜像选择：使用alpine/slim/distroless最小化镜像。多阶段构建（Multi-stage Build）：构建阶段用完整镜像，运行阶段只复制产物到最小镜像。减少层数：合并RUN指令、清理安装缓存（`rm -rf /var/cache/apt/*`）。合理利用缓存：频繁变化的层放后面。安全：不以root运行（USER指令）、不在镜像中存储密钥。.dockerignore排除无关文件。

### 11. Kubernetes的核心架构是什么？请描述Master和Node的关键组件及其职责。
- **难度**：中等
- **考察点**：K8s架构理解
- **要点**：Master组件：kube-apiserver（API入口，认证授权准入控制）、etcd（分布式KV存储，集群状态数据）、kube-scheduler（调度Pod到合适Node）、kube-controller-manager（运行各种控制器如Deployment/ReplicaSet/Node控制器）。Node组件：kubelet（管理Pod生命周期，与容器运行时交互）、kube-proxy（维护网络规则，实现Service负载均衡）、容器运行时（containerd/CRI-O）。

### 12. 请解释Kubernetes中Pod、Deployment、Service、Ingress的关系和各自作用。
- **难度**：中等
- **考察点**：K8s核心资源理解
- **要点**：Pod是最小调度单元，包含一个或多个容器。Deployment管理Pod的副本数和滚动更新策略，确保期望状态。Service提供稳定的网络访问入口（ClusterIP/NodePort/LoadBalancer），通过Label Selector关联Pod，实现负载均衡和服务发现。Ingress是七层（HTTP/HTTPS）入口，基于域名和路径路由到不同Service，由Ingress Controller（如Nginx Ingress）实现。

### 13. Kubernetes中如何实现滚动更新和回滚？如何保证发布过程中的服务可用性？
- **难度**：中高
- **考察点**：K8s发布策略
- **要点**：Deployment的rollingUpdate策略：maxSurge（最多额外创建的Pod数）、maxUnavailable（最多不可用Pod数）。更新过程：创建新ReplicaSet → 逐步增加新Pod → 逐步减少旧Pod。回滚：`kubectl rollout undo deployment/xxx --to-revision=N`。可用性保障：readinessProbe（就绪探针，Pod就绪后才接收流量）、livenessProbe（存活探针，失败重启）、PodDisruptionBudget（最小可用Pod数）、preStop hook（优雅关闭）。

## 四、CI/CD（4题）

### 14. 请描述一个完整的CI/CD流水线设计，从代码提交到生产部署。
- **难度**：中等
- **考察点**：CI/CD流程设计
- **要点**：代码提交 → 触发CI → 代码检出 → 静态代码分析（SonarQube） → 单元测试 → 构建（编译/打包/镜像构建）→ 推送镜像到Registry → 部署到测试环境 → 集成测试/接口测试 → 人工审批（生产环境）→ 灰度发布 → 全量发布 → 监控验证。流水线工具：Jenkins Pipeline/GitLab CI/GitHub Actions/ArgoCD。

### 15. Jenkins Pipeline和GitLab CI的区别是什么？你在项目中是如何选型的？
- **难度**：中等
- **考察点**：CI/CD工具选型
- **要点**：Jenkins：插件生态丰富、灵活性强、支持复杂编排，但维护成本高、UI老旧。Pipeline as Code（Jenkinsfile）。GitLab CI：与GitLab深度集成、YAML配置简洁、内置Container Registry和Docker支持，但灵活性不如Jenkins、插件生态较弱。选型依据：代码托管平台、团队技术栈、流程复杂度。GitHub生态可选GitHub Actions，K8s生态可选ArgoCD（GitOps）。

### 16. 什么是GitOps？它与传统CI/CD有什么区别？
- **难度**：中高
- **考察点**：现代运维理念
- **要点**：GitOps以Git仓库作为部署的唯一事实来源（Single Source of Truth），通过声明式配置描述期望状态，由自动化工具（ArgoCD/Flux）持续监控Git仓库并将集群状态同步到期望状态。区别：传统CI/CD是push模式（流水线推送到集群），GitOps是pull模式（集群拉取配置）。优点：全审计追踪、易回滚（git revert）、一致性保证、安全性更高（集群不需要暴露给CI）。

### 17. 如何实现蓝绿部署和金丝雀发布？各自适用什么场景？
- **难度**：中等
- **考察点**：发布策略
- **要点**：蓝绿部署：维护两套完全相同的环境（蓝色当前版本、绿色新版本），切换流量到绿色后蓝色作为回滚。优点：回滚快（秒级切换），缺点：资源消耗翻倍。金丝雀发布：将少量流量（如5%）导向新版本，观察无异常后逐步增加比例。优点：风险可控，缺点：灰度期间维护两个版本。K8s实现：Istio/Nginx Ingress权重路由。适用：蓝绿适合对回滚速度要求高的场景，金丝雀适合大流量逐步验证。

## 五、监控与日志（3题）

### 18. 请描述Prometheus+Grafana的监控架构和核心工作原理。
- **难度**：中等
- **考察点**：监控系统设计
- **要点**：Prometheus采用pull模式，定期从exporter/应用的metrics端点抓取指标数据，存储在本地TSDB中。核心组件：Prometheus Server（采集存储）、Exporters（暴露指标，如node_exporter、mysqld_exporter）、Alertmanager（告警通知路由、静默、抑制）、PushGateway（短生命周期任务推送指标）。数据模型：指标名+标签键值对，四种类型（Counter/Gauge/Histogram/Summary）。PromQL查询语言。Grafana负责可视化展示。

### 19. ELK（Elasticsearch+Logstash+Kibana）日志系统的架构是什么？如何处理大规模日志？
- **难度**：中等
- **考察点**：日志系统设计
- **要点**：经典架构：应用 → Filebeat（轻量采集）→ Kafka（缓冲削峰）→ Logstash（解析转换）→ Elasticsearch（存储索引）→ Kibana（可视化查询）。大规模处理：Kafka做消息缓冲防止ES写入过载、ES集群水平扩展（分片+副本）、冷热数据分层（Hot-Warm-Cold架构）、ILM（Index Lifecycle Management）自动管理索引生命周期。日志格式标准化：JSON结构化日志，统一字段命名。

### 20. 你在项目中如何设计告警策略？如何避免告警风暴和告警疲劳？
- **难度**：中高
- **考察点**：告警体系设计
- **要点**：告警分级：P0紧急（服务不可用，电话+短信立即响应）、P1高优先（核心功能受损，短信+IM通知）、P2中优先（非核心告警，IM通知）、P3低优先（日报汇总）。避免告警风暴：设置合理阈值和持续时间（如CPU>90%持续5分钟才告警）、告警分组聚合（同类告警合并）、告警抑制（上游服务故障抑制下游告警）。避免告警疲劳：定期Review告警规则、删除不再有效的告警、每个告警附带RunBook（处理手册）。

## 六、网络与安全（3题）

### 21. 请解释TCP三次握手和四次挥手的过程。TIME_WAIT状态的作用是什么？大量TIME_WAIT如何处理？
- **难度**：中等
- **考察点**：网络基础
- **要点**：三次握手：SYN → SYN+ACK → ACK。四次挥手：FIN → ACK → FIN → ACK。TIME_WAIT：主动关闭方在发送最后一个ACK后进入，持续2MSL（通常60秒），确保最后ACK到达对方+让旧连接的包过期。大量TIME_WAIT处理：调整`net.ipv4.tcp_tw_reuse=1`（允许重用TIME_WAIT连接）、使用连接池减少短连接、应用层使用长连接（Keep-Alive）。

### 22. HTTPS的工作原理是什么？如何在Nginx中配置SSL证书？
- **难度**：中等
- **考察点**：网络安全
- **要点**：HTTPS = HTTP + TLS。握手过程：客户端发送支持的加密套件 → 服务端返回证书和选定算法 → 客户端验证证书有效性 → 双方协商对称密钥（RSA或ECDHE）→ 使用对称密钥加密通信。Nginx配置：listen 443 ssl、ssl_certificate和ssl_certificate_key指定证书和私钥、ssl_protocols指定TLS版本（禁用TLSv1.0/1.1）、ssl_ciphers指定加密套件、启用HSTS和OCSP Stapling。Let's Encrypt免费证书+certbot自动续期。

### 23. 常见的服务器安全加固措施有哪些？
- **难度**：中等
- **考察点**：安全运维
- **要点**：系统层面：禁用root远程登录、使用SSH密钥认证、修改SSH端口、配置fail2ban防暴力破解、最小化安装（删除不需要的软件包）、定期安全更新。网络层面：iptables/nftables防火墙只开放必要端口、配置安全组、使用VPN访问内网。应用层面：WAF防护、定期漏洞扫描（Nessus/OpenVAS）、文件完整性监控（AIDE）。权限层面：最小权限原则、sudo精细化配置、定期审计用户和权限。日志层面：开启审计日志（auditd）、日志集中管理、异常登录告警。

## 七、云平台（2题）

### 24. 请对比公有云（AWS/阿里云）中的核心服务，如计算、存储、网络等。
- **难度**：中等
- **考察点**：云平台理解
- **要点**：计算：EC2/ECS（弹性服务器）、Lambda/函数计算（Serverless）、EKS/ACK（托管K8s）。存储：S3/OSS（对象存储）、EBS/云盘（块存储）、EFS/NAS（文件存储）。网络：VPC（虚拟私有云）、ELB/SLB（负载均衡）、Route53/云解析（DNS）、CloudFront/CDN（内容分发）。数据库：RDS（托管数据库）、DynamoDB/表格存储（NoSQL）、ElastiCache/Redis（缓存）。关键概念：可用区（AZ）、区域（Region）、弹性伸缩（Auto Scaling）。

### 25. 如何设计一个高可用的云架构？请从计算、存储、网络和容灾四个方面说明。
- **难度**：中高
- **考察点**：架构设计能力
- **要点**：计算：多AZ部署+Auto Scaling弹性伸缩+健康检查自动替换。存储：数据多副本存储（S3/OSS 99.999999999%持久性）、数据库主从复制+自动故障转移（RDS Multi-AZ）、定期备份+跨区域备份。网络：负载均衡（ALB/SLB）多AZ分发流量、DNS故障转移（Route53 Health Check）、CDN加速+回源容灾。容灾：RPO/RTO指标定义、异地多活或主备架构、定期容灾演练、混沌工程验证（Chaos Monkey）。目标：SLA 99.99%（年停机时间<53分钟）。
