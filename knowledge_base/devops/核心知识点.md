## 一、Linux系统管理

### 1.1 文件系统与权限
- **文件系统层级**：/（根）、/etc（配置）、/var（日志/数据）、/usr（用户程序）、/tmp（临时）、/home（用户目录）、/proc（虚拟文件系统，内核和进程信息）
- **权限体系**：rwx（读写执行）、Owner/Group/Others三组权限
- **特殊权限**：SUID（4000）、SGID（2000）、Sticky Bit（1000）
- **ACL扩展权限**：`setfacl -m u:user:rwx file`，更精细的权限控制
- **文件属性**：`lsattr`/`chattr`，不可变属性（+i）、仅追加属性（+a）

### 1.2 进程与服务管理
- **进程查看**：`ps aux`、`top`/`htop`、`pstree`、`/proc/PID/`
- **进程控制**：`kill -9`（强制终止）、`kill -15`（优雅终止）、`nohup`（后台运行）、`&`
- **systemd服务管理**：
  ```bash
  systemctl start/stop/restart/status/enable/disable service
  systemctl list-units --type=service
  journalctl -u service -f  # 查看服务日志
  ```
- **Unit文件编写**：`/etc/systemd/system/xxx.service`
  ```ini
  [Unit]
  Description=My Service
  After=network.target

  [Service]
  Type=simple
  User=app
  ExecStart=/usr/bin/myapp
  Restart=on-failure
  RestartSec=5

  [Install]
  WantedBy=multi-user.target
  ```

### 1.3 性能监控与排查
- **CPU**：`top`（%us用户态、%sy内核态、%wa IO等待）、`mpstat -P ALL`、`perf top`
- **内存**：`free -h`、`vmstat 1`（si/so交换）、`/proc/meminfo`
- **磁盘IO**：`iostat -x 1`（await/util）、`iotop`（进程IO排行）
- **网络**：`netstat -tlnp`/`ss -tlnp`（监听端口）、`iftop`（流量）、`tcpdump`（抓包）
- **综合**：`dstat`、`sar`（历史数据）、`nmon`

### 1.4 磁盘与存储管理
- **磁盘分区**：fdisk/gdisk/parted
- **LVM逻辑卷管理**：PV（物理卷）→ VG（卷组）→ LV（逻辑卷），支持动态扩容
- **文件系统**：ext4（稳定）、xfs（高性能大文件）、btrfs（快照功能）
- **RAID级别**：RAID0（条带化，高性能无冗余）、RAID1（镜像）、RAID5（条带+校验，至少3盘）、RAID10（镜像+条带）
- **NFS/CIFS**：网络文件共享

## 二、Shell脚本编程

### 2.1 基础语法
```bash
#!/bin/bash

# 变量
NAME="DevOps"
readonly VERSION="1.0"

# 条件判断
if [ -f "$FILE" ]; then
    echo "文件存在"
elif [ -d "$DIR" ]; then
    echo "目录存在"
fi

# 循环
for i in {1..10}; do echo $i; done
while read line; do echo "$line"; done < file.txt

# 函数
function check_service() {
    local service_name=$1
    systemctl is-active "$service_name" > /dev/null 2>&1
    return $?
}

# 数组
arr=("a" "b" "c")
echo ${arr[@]}    # 所有元素
echo ${#arr[@]}   # 数组长度
```

### 2.2 文本处理三剑客
- **grep**：文本搜索
  ```bash
  grep -rn "error" /var/log/   # 递归搜索，显示行号
  grep -E "error|warn" file    # 正则匹配（等同egrep）
  grep -c "pattern" file       # 统计匹配行数
  grep -v "pattern" file       # 反向匹配
  ```
- **sed**：流编辑器
  ```bash
  sed 's/old/new/g' file       # 全局替换
  sed -i '3d' file             # 删除第3行（原地修改）
  sed -n '10,20p' file         # 打印10-20行
  sed '/pattern/a\new line' file  # 在匹配行后追加
  ```
- **awk**：文本分析
  ```bash
  awk '{print $1, $3}' file            # 打印第1和第3列
  awk -F: '$3>=1000 {print $1}' /etc/passwd  # 指定分隔符+条件
  awk '{sum+=$1} END {print sum}' file  # 求和
  awk 'NR>=10 && NR<=20' file          # 打印10-20行
  ```

### 2.3 实用脚本模式
- **日志记录**：函数封装log_info/log_error，输出时间戳和级别
- **错误处理**：`set -euo pipefail`，`trap` 捕获信号做清理
- **参数解析**：`getopts` 或 `$1/$2` 位置参数
- **锁机制**：`flock` 文件锁防止脚本并发执行
- **配置文件**：`source config.sh` 加载外部配置

## 三、Docker容器原理

### 3.1 核心技术
- **Namespace隔离**：
  | Namespace | 隔离资源 |
  |-----------|---------|
  | PID | 进程ID |
  | Network | 网络栈（网卡/IP/端口/路由） |
  | Mount | 文件系统挂载点 |
  | UTS | 主机名和域名 |
  | IPC | 信号量、消息队列、共享内存 |
  | User | 用户和用户组 |

- **Cgroups资源限制**：
  ```bash
  docker run --cpus="1.5" --memory="512m" --memory-swap="1g" image
  ```
  控制CPU份额/核数、内存上限、磁盘IO带宽、进程数等

- **UnionFS分层存储**：
  镜像由多个只读层叠加，容器运行时在顶部添加一个可写层（Copy-on-Write）。存储驱动：overlay2（推荐）、devicemapper、btrfs

### 3.2 网络模式
| 模式 | 说明 | 使用场景 |
|------|------|---------|
| bridge | 默认，Docker创建虚拟网桥docker0 | 单机容器互联 |
| host | 共享宿主机网络栈 | 高性能网络需求 |
| none | 无网络 | 安全隔离场景 |
| overlay | 跨主机容器网络 | Docker Swarm/多节点 |
| macvlan | 容器获得独立MAC地址 | 需要直接接入物理网络 |

### 3.3 数据管理
- **Volume**：`docker volume create`，Docker管理的持久化存储，推荐
- **Bind Mount**：`-v /host/path:/container/path`，直接映射宿主机目录
- **tmpfs**：内存临时存储，容器停止后消失

### 3.4 Docker Compose
```yaml

services:
  web:
    build: ./web
    ports:

  db_data:
```

## 四、Kubernetes核心概念

### 4.1 核心架构
```
Master Node:
├── kube-apiserver       # API入口，认证/授权/准入控制
├── etcd                 # 分布式KV存储，集群状态数据
├── kube-scheduler       # Pod调度到合适Node
└── kube-controller-manager  # 控制器（Deployment/ReplicaSet/Node/Job等）

Worker Node:
├── kubelet              # 管理Pod生命周期
├── kube-proxy           # Service网络代理和负载均衡
└── Container Runtime    # containerd / CRI-O
```

### 4.2 核心资源对象
| 资源 | 作用 | 说明 |
|------|------|------|
| Pod | 最小调度单元 | 一个或多个容器+共享存储/网络 |
| Deployment | 无状态应用管理 | 副本管理、滚动更新、回滚 |
| StatefulSet | 有状态应用管理 | 稳定网络标识、有序部署和扩缩 |
| DaemonSet | 每个Node运行一个Pod | 日志采集、监控Agent |
| Job/CronJob | 一次性/定时任务 | 批处理、定时清理 |
| Service | 服务发现和负载均衡 | ClusterIP/NodePort/LoadBalancer |
| Ingress | 七层路由 | 域名+路径路由到Service |
| ConfigMap | 配置管理 | 非敏感配置数据 |
| Secret | 敏感数据管理 | 密码、密钥、证书（Base64编码） |
| PV/PVC | 持久化存储 | PV定义存储、PVC申请存储 |
| HPA | 自动水平扩缩 | 基于CPU/内存/自定义指标自动调整副本数 |

### 4.3 Service网络
- **ClusterIP**：集群内部访问（默认），虚拟IP
- **NodePort**：通过Node的端口暴露服务（30000-32767）
- **LoadBalancer**：云平台负载均衡器
- **ExternalName**：CNAME映射到外部服务
- **实现原理**：kube-proxy通过iptables/IPVS规则实现流量转发

### 4.4 调度与亲和性
- **nodeSelector**：简单的Node标签选择
- **nodeAffinity**：更灵活的Node亲和性规则（required/preferred）
- **podAffinity/podAntiAffinity**：Pod间亲和/反亲和（如将Web和Cache部署到同一Node）
- **Taint/Toleration**：Node打污点 + Pod设置容忍，实现特殊调度（如GPU节点专用）
- **资源请求与限制**：requests（调度依据）和limits（运行上限）

## 五、Jenkins/GitLab CI

### 5.1 Jenkins Pipeline
```groovy
pipeline {
    agent any

    environment {
        REGISTRY = 'registry.example.com'
        IMAGE_TAG = "${env.BUILD_NUMBER}"
    }

    stages {
        stage('Checkout') {
            steps {
                git branch: 'main', url: 'https://github.com/example/repo.git'
            }
        }
        stage('Build') {
            steps {
                sh 'mvn clean package -DskipTests'
            }
        }
        stage('Test') {
            parallel {
                stage('Unit Test') { steps { sh 'mvn test' } }
                stage('SonarQube') { steps { sh 'mvn sonar:sonar' } }
            }
        }
        stage('Docker Build & Push') {
            steps {
                sh "docker build -t ${REGISTRY}/app:${IMAGE_TAG} ."
                sh "docker push ${REGISTRY}/app:${IMAGE_TAG}"
            }
        }
        stage('Deploy') {
            steps {
                sh "kubectl set image deployment/app app=${REGISTRY}/app:${IMAGE_TAG}"
            }
        }
    }

    post {
        success { slackSend color: 'good', message: "构建成功: ${env.JOB_NAME} #${env.BUILD_NUMBER}" }
        failure { slackSend color: 'danger', message: "构建失败: ${env.JOB_NAME} #${env.BUILD_NUMBER}" }
    }
}
```

## 六、Prometheus + Grafana

### 6.1 Prometheus架构
```
Targets (Exporters) ──pull──> Prometheus Server ──> TSDB存储
                                    │
                                    ├──> Grafana (可视化)
                                    ├──> Alertmanager (告警)
                                    └──> API (查询)
```

### 6.2 核心指标类型
| 类型 | 说明 | 示例 |
|------|------|------|
| Counter | 只增不减的计数器 | http_requests_total |
| Gauge | 可增可减的瞬时值 | memory_usage_bytes |
| Histogram | 分布统计（桶计数） | http_request_duration_seconds |
| Summary | 分布统计（百分位数） | go_gc_duration_seconds |

### 6.3 PromQL查询语言
```promql
# 查询HTTP请求速率
rate(http_requests_total[5m])

# 查询CPU使用率
100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 查询内存使用率
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100

# P95响应时间
histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))

# 告警规则
alert: HighErrorRate
expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
for: 5m
labels:
  severity: critical
annotations:
  summary: "HTTP 5xx错误率超过5%"
```

### 6.4 常用Exporter
- **node_exporter**：服务器CPU、内存、磁盘、网络指标
- **mysqld_exporter**：MySQL性能指标
- **redis_exporter**：Redis指标
- **blackbox_exporter**：HTTP/TCP/ICMP探测（外部监控）
- **cadvisor**：容器资源使用指标

## 七、ELK日志系统

### 7.1 组件职责
- **Elasticsearch**：分布式搜索和分析引擎，存储和索引日志数据
- **Logstash**：数据采集和转换管道（Input → Filter → Output）
- **Kibana**：可视化平台（搜索、仪表盘、告警）
- **Filebeat**：轻量级日志采集器，替代Logstash做采集

### 7.2 推荐架构
```
应用日志 → Filebeat(采集) → Kafka(缓冲) → Logstash(解析) → Elasticsearch(存储) → Kibana(可视化)
```

### 7.3 Logstash配置示例
```ruby
input {
  kafka {
    bootstrap_servers => "kafka:9092"
    topics => ["app-logs"]
    group_id => "logstash-consumer"
  }
}

filter {
  json { source => "message" }
  date { match => ["timestamp", "yyyy-MM-dd HH:mm:ss"] }
  grok {
    match => { "message" => "%{IP:client_ip} %{WORD:method} %{URIPATH:path} %{NUMBER:status}" }
  }
  mutate { remove_field => ["@version", "host"] }
}

output {
  elasticsearch {
    hosts => ["es:9200"]
    index => "app-logs-%{+YYYY.MM.dd}"
  }
}
```

### 7.4 Elasticsearch运维要点
- **集群规划**：Master节点（3个，奇数防脑裂）、Data节点、Coordinating节点
- **索引管理**：分片数（创建后不可修改）、副本数、ILM生命周期策略
- **性能优化**：合理设置分片大小（20-50GB）、bulk批量写入、refresh_interval调优
- **冷热架构**：热节点（SSD存近期数据）、温节点、冷节点（HDD存历史数据）

## 八、Nginx

### 8.1 核心功能
- **Web服务器**：静态文件服务、目录浏览
- **反向代理**：代理后端服务、隐藏后端结构
- **负载均衡**：round-robin（轮询）、least_conn（最少连接）、ip_hash（会话保持）、weighted（权重）
- **缓存**：proxy_cache缓存后端响应
- **SSL终止**：TLS卸载，后端使用HTTP

### 8.2 常用配置
```nginx
# 反向代理 + 负载均衡
upstream backend {
    least_conn;
    server 10.0.0.1:8080 weight=3;
    server 10.0.0.2:8080 weight=2;
    server 10.0.0.3:8080 backup;  # 备份服务器
}

server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    # 安全头
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options DENY;
    add_header Strict-Transport-Security "max-age=31536000" always;

    # 静态文件
    location /static/ {
        root /var/www;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # API代理
    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_connect_timeout 5s;
        proxy_read_timeout 30s;
    }

    # 限流
    limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
    location /api/login {
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://backend;
    }
}
```

### 8.3 性能优化
- **worker_processes**：设为CPU核心数或auto
- **worker_connections**：单个worker的最大连接数（通常10240+）
- **keepalive_timeout**：长连接超时时间
- **gzip压缩**：开启gzip压缩文本响应（gzip_types配置）
- **sendfile**：启用零拷贝文件传输
- **open_file_cache**：文件描述符缓存

## 九、Ansible/Terraform

### 9.1 Ansible（配置管理）
- **架构**：无Agent，通过SSH连接被管理节点
- **核心概念**：Inventory（主机清单）、Playbook（剧本）、Role（角色）、Module（模块）
- **Playbook示例**：
  ```yaml
  ---
  - hosts: webservers
    become: yes
    vars:
      app_version: "2.0.1"

    tasks:
      - name: Install Nginx
        apt:
          name: nginx
          state: present
          update_cache: yes

      - name: Copy config
        template:
          src: nginx.conf.j2
          dest: /etc/nginx/nginx.conf
        notify: Restart Nginx

      - name: Ensure Nginx is running
        service:
          name: nginx
          state: started
          enabled: yes

    handlers:
      - name: Restart Nginx
        service:
          name: nginx
          state: restarted
  ```
- **最佳实践**：使用Role组织代码、Ansible Vault加密敏感数据、幂等性保证、使用Tags按需执行

### 9.2 Terraform（基础设施即代码）
- **核心概念**：Provider（云平台适配）、Resource（资源定义）、State（状态管理）、Module（可复用模块）
- **工作流程**：`terraform init` → `terraform plan` → `terraform apply` → `terraform destroy`
- **HCL配置示例**：
  ```hcl
  provider "aws" {
    region = "ap-northeast-1"
  }

  resource "aws_instance" "web" {
    ami           = "ami-0c55b159cbfafe1f0"
    instance_type = "t3.medium"
    count         = 3

    tags = {
      Name        = "web-${count.index}"
      Environment = "production"
    }
  }

  resource "aws_lb" "web" {
    name               = "web-lb"
    load_balancer_type = "application"
    subnets            = var.subnet_ids
  }
  ```
- **状态管理**：远程Backend（S3+DynamoDB锁、Terraform Cloud）防止状态冲突
- **最佳实践**：模块化组织、环境隔离（workspace或目录）、代码审查terraform plan输出、版本锁定Provider
