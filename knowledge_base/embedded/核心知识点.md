# 嵌入式工程师核心知识点

---

## 一、C语言指针、内存管理、volatile/const

### 1.1 指针深入理解
- **指针的本质**：存储内存地址的变量，大小取决于平台（32位系统4字节，64位系统8字节）
- **多级指针**：`int **pp` 指向指针的指针，常用于函数内修改指针指向
- **函数指针**：`int (*func_ptr)(int, int)`，嵌入式中广泛用于回调函数、状态机跳转表、中断向量表
- **指针运算**：加减运算以所指类型大小为单位，`int *p; p+1` 地址增加4字节
- **void指针**：通用指针类型，不能直接解引用，需强制类型转换，常用于通用接口设计
- **restrict指针**：C99关键字，告知编译器该指针是访问对象的唯一方式，允许更积极的优化

### 1.2 内存管理
- **内存区域**：代码段（.text）、只读数据段（.rodata）、已初始化数据段（.data）、未初始化数据段（.bss）、堆（heap）、栈（stack）
- **嵌入式内存布局**：由链接脚本（.ld）定义，Flash存放代码和常量，RAM存放变量和栈
- **动态内存分配**：裸机中尽量避免使用malloc/free（碎片化、不确定性），RTOS提供内存池管理（FreeRTOS的pvPortMalloc/vPortFree有5种分配策略）
- **栈溢出**：嵌入式中栈空间有限（几KB），递归和大局部数组是主要风险，RTOS可配置栈溢出检测
- **内存泄漏检测**：裸机中需人工审查，Linux环境可用Valgrind、mtrace

### 1.3 volatile关键字
- **作用**：防止编译器优化，每次访问都从内存读取
- **应用场景**：
  - 硬件寄存器：`volatile uint32_t *reg = (volatile uint32_t *)0x40021000;`
  - 中断中修改的变量：ISR与主循环共享的flag
  - 多线程/多核共享变量
  - DMA缓冲区
- **注意**：volatile不保证原子性，不能替代互斥保护

### 1.4 const关键字
- **const变量**：编译器禁止修改，但底层内存可能仍可通过指针修改
- **const与指针**：`const int *p`（指向常量的指针）vs `int *const p`（常量指针）vs `const int *const p`（都不可变）
- **嵌入式用途**：将常量表放入Flash节省RAM，用 `const` 修饰配置参数表、字库数据等

## 二、RTOS（FreeRTOS）任务调度、信号量、互斥锁

### 2.1 任务调度
- **调度算法**：基于优先级的抢占式调度 + 同优先级时间片轮转
- **任务状态**：运行（Running）、就绪（Ready）、阻塞（Blocked）、挂起（Suspended）
- **任务创建**：`xTaskCreate()` 动态创建，`xTaskCreateStatic()` 静态创建
- **空闲任务**：优先级最低（0），系统保证至少运行空闲任务，可在其中执行低优先级工作或进入低功耗
- **调度时机**：更高优先级任务就绪、当前任务阻塞、调用 `taskYIELD()`、时间片到期

### 2.2 信号量
- **二值信号量**：用于任务同步（如ISR通知任务），初始值为0
- **计数信号量**：用于资源计数和事件计数
- **API**：`xSemaphoreGive()` / `xSemaphoreTake()` / `xSemaphoreGiveFromISR()`
- **注意**：信号量不解决优先级反转问题

### 2.3 互斥锁（Mutex）
- **与信号量区别**：支持优先级继承、必须由获取者释放、不能在ISR中使用
- **优先级继承**：低优先级任务持有Mutex时，如果高优先级任务等待，低优先级任务临时提升到高优先级
- **递归互斥锁**：允许同一任务多次获取，需相同次数释放
- **死锁预防**：固定加锁顺序、使用超时机制、减小临界区

### 2.4 其他同步机制
- **队列（Queue）**：任务间数据传递，值传递（拷贝数据），支持ISR版本API
- **事件标志组（Event Group）**：多事件等待，支持AND/OR组合
- **任务通知（Task Notification）**：轻量级（无需创建对象），可替代二值信号量/计数信号量/事件标志组
- **软件定时器**：在定时器任务中执行回调，不在ISR中运行

## 三、中断处理机制

### 3.1 中断基本概念
- **中断源**：外部中断（GPIO、外部信号）、内部中断（定时器、DMA完成、UART接收）、异常（Hard Fault、Memory Fault）
- **中断向量表**：存储各中断服务程序（ISR）入口地址，通常在启动文件中定义
- **中断优先级**：数值越小优先级越高（Cortex-M），分为抢占优先级和子优先级

### 3.2 中断处理流程（Cortex-M）
1. 硬件自动压栈（xPSR、PC、LR、R12、R3-R0）
2. 查中断向量表获取ISR地址
3. 切换到Handler模式，使用MSP
4. 执行ISR
5. 硬件自动出栈，恢复现场
6. **尾链优化**：连续中断时跳过出栈/入栈过程

### 3.3 ISR编程规范
- **快进快出**：ISR中只做最少必要操作，复杂处理交给任务（上半部/下半部）
- **禁止阻塞**：不能调用可能阻塞的API（如 `xSemaphoreTake` 无超时版）
- **使用FromISR版API**：FreeRTOS中ISR必须使用 `xSemaphoreGiveFromISR()` 等带FromISR后缀的函数
- **volatile标记共享变量**
- **临界区保护**：`taskENTER_CRITICAL_FROM_ISR()` / `taskEXIT_CRITICAL_FROM_ISR()`

### 3.4 中断延迟
- **中断延迟**：从中断请求到ISR首条指令执行的时间
- **影响因素**：当前指令执行时间、高优先级中断占用、临界区关中断时间
- **优化**：减少关中断时间、使用BASEPRI替代PRIMASK（只屏蔽部分优先级）

## 四、DMA原理

### 4.1 DMA基本概念
- **DMA（Direct Memory Access）**：数据传输不经过CPU，由DMA控制器直接搬运
- **传输方向**：内存→外设、外设→内存、内存→内存
- **优势**：释放CPU算力，适合大批量数据传输（ADC采集、SPI通信、UART收发）

### 4.2 DMA配置要素
- **源地址和目标地址**
- **传输数据宽度**：字节/半字/字
- **传输数量**
- **地址递增模式**：源/目标地址是否自动递增
- **传输模式**：普通模式（传完停止）/ 循环模式（自动重载）
- **优先级**：多个DMA通道同时请求时的仲裁
- **FIFO模式**：突发传输，提高效率

### 4.3 DMA与中断配合
- 传输完成中断（TC）：通知CPU数据搬运完毕
- 半传输中断（HT）：配合双缓冲实现数据流不间断处理
- 传输错误中断（TE）：总线错误等异常
- **双缓冲模式**：DMA填充A缓冲区时CPU处理B缓冲区，交替进行

### 4.4 注意事项
- DMA缓冲区需用 `volatile` 修饰
- Cache一致性问题（Cortex-M7及以上）：需 `SCB_CleanDCache()` / `SCB_InvalidateDCache()`
- DMA缓冲区地址对齐要求

## 五、嵌入式Linux驱动开发流程

### 5.1 驱动分类
- **字符设备驱动**：按字节流访问（串口、LED、按键、传感器）
- **块设备驱动**：按块访问（Flash、SD卡、磁盘）
- **网络设备驱动**：网络接口（以太网、WiFi）

### 5.2 字符设备驱动开发流程
1. **分配设备号**：`alloc_chrdev_region()` 动态分配主次设备号
2. **初始化cdev**：`cdev_init()` 绑定 `file_operations`
3. **注册cdev**：`cdev_add()` 向内核注册
4. **创建设备类和节点**：`class_create()` + `device_create()` 自动创建 `/dev/xxx`
5. **实现file_operations**：open/read/write/ioctl/release
6. **模块入口/出口**：`module_init()` / `module_exit()`

### 5.3 设备树（Device Tree）
- **DTS/DTSI文件**：描述硬件信息（寄存器地址、中断号、时钟、引脚复用）
- **DTB文件**：编译后的二进制格式，由Bootloader传给内核
- **驱动中解析设备树**：`of_property_read_u32()`、`of_get_gpio()`、`platform_get_resource()`
- **compatible属性**：驱动与设备的匹配依据

### 5.4 Platform驱动模型
- **分离思想**：将设备信息（设备树/platform_device）与驱动逻辑（platform_driver）分离
- **匹配机制**：设备树compatible → ACPI → id_table → name
- **probe函数**：匹配成功后调用，执行硬件初始化
- **remove函数**：设备移除时调用，释放资源

## 六、通信协议

### 6.1 UART（通用异步收发器）
- **特点**：异步、全双工、点对点
- **帧格式**：起始位(1) + 数据位(5-9) + 校验位(可选) + 停止位(1-2)
- **波特率**：常用9600/115200/921600
- **硬件流控**：RTS/CTS防止数据丢失
- **应用**：调试串口、GPS模块、蓝牙模块

### 6.2 I2C（两线式串行总线）
- **信号线**：SDA（数据线）+ SCL（时钟线），开漏输出需上拉电阻
- **通信过程**：START → 设备地址(7/10bit) + R/W → ACK → 数据 → ACK → STOP
- **速度**：标准100kbps、快速400kbps、高速3.4Mbps
- **多主多从**：通过地址寻址，支持总线仲裁
- **应用**：EEPROM、温湿度传感器、OLED屏、RTC

### 6.3 SPI（串行外设接口）
- **信号线**：MOSI、MISO、SCLK、CS（片选）
- **四种模式**：CPOL（时钟空闲极性）和CPHA（采样边沿）组合
- **特点**：全双工、速度快（可达几十Mbps）、无应答机制
- **应用**：Flash存储、LCD屏、ADC/DAC、SD卡（SPI模式）

### 6.4 CAN（控制器局域网）
- **物理层**：差分信号（CAN_H、CAN_L），120Ω终端电阻
- **帧类型**：数据帧、远程帧、错误帧、过载帧
- **仲裁机制**：非破坏性位仲裁，ID小的优先级高
- **错误处理**：CRC校验、位填充、错误计数器（主动错误/被动错误/总线关闭）
- **CAN FD**：支持更高速率（最高8Mbps）和更大数据域（64字节）

## 七、低功耗设计

### 7.1 低功耗模式（以STM32为例）
- **Sleep模式**：CPU停止，外设运行，任意中断唤醒
- **Stop模式**：所有时钟停止，RAM和寄存器保持，EXTI/RTC唤醒
- **Standby模式**：最低功耗，RAM丢失，WKUP引脚/RTC唤醒，相当于复位

### 7.2 软件层面优化
- 降低CPU主频（动态频率调节）
- 关闭不用的外设时钟
- 使用中断/事件驱动代替轮询
- 合理使用DMA减少CPU唤醒
- 优化算法减少运算时间

### 7.3 硬件层面优化
- 选择低功耗器件
- 电源域划分，不用模块断电
- 使用LDO/DC-DC转换器提高效率
- 减少上拉/下拉电阻导致的静态功耗
- 合理设计PCB降低漏电流

### 7.4 功耗测量
- 使用电流探头+示波器观察电流波形
- 使用低功耗分析仪（如Nordic PPK2）
- 注意测量方法：串联电阻法、高精度电流表

## 八、启动流程（Bootloader）

### 8.1 MCU启动流程（以Cortex-M为例）
1. 上电/复位后从固定地址（0x00000000或0x08000000）读取初始SP值
2. 从偏移0x04读取Reset_Handler地址并跳转
3. Reset_Handler中：初始化.data段（从Flash拷贝到RAM）、清零.bss段
4. 初始化系统时钟（SystemInit）
5. 调用C库初始化（__libc_init_array）
6. 跳转到main()

### 8.2 Bootloader设计
- **功能**：固件升级（OTA/UART/USB）、安全启动、多固件管理
- **内存布局**：Bootloader区 + App1区 + App2区（可选）+ 参数区
- **跳转机制**：设置MSP → 跳转到App的Reset_Handler
- **升级策略**：A/B分区（安全但占空间）、单分区覆盖（省空间但有变砖风险）

### 8.3 嵌入式Linux启动流程
1. **Boot ROM**：芯片内置，初始化基本硬件，加载SPL
2. **SPL（Secondary Program Loader）**：初始化DDR，加载U-Boot
3. **U-Boot**：全功能Bootloader，初始化外设、网络，加载内核和设备树
4. **Linux内核**：解压、初始化子系统、挂载根文件系统
5. **Init进程**：PID=1，启动用户空间服务
6. **应用程序**：系统就绪，运行业务程序
